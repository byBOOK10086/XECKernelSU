# 质量闸门：防止再长成旧仓那样

> 旧仓的乱不是一天长成的，是"每一轮都在加、但没有任何一条边界被机械地守住"。
> 这份文档把边界写清楚，每条都由 `scripts/check_quality.py` 强制，CI 里跑，违反就红。

## 机制：预算（ratchet），不是禁令

现有代码里已经有大的东西，一刀切禁令只会让人绕过闸门。所以规则是：

- **新文件**：≤ 400 行（Kotlin / Rust / C / 脚本）
- **已超标的文件**：登记在 `scripts/quality-baseline.json`，**只能变小，不能变大**
- 每次拆分后，把预算调小；文件达标后**删掉条目**才算完成

这条对上游文件同样生效（如 `userspace/ksud/src/lkm_image.rs` 3,301 行）：我们不拆别人的文件，但**也不允许它继续长**。

## 六条闸门

| # | 闸门 | 违规示例（旧仓真实发生过） |
|---|---|---|
| 1 | 单文件 ≤400 行 / 预算只能降 | 19 个 ≥600 行的文件，最大 1,812 行 |
| 2 | 语言目录数量封顶（当前 48：上游翻译 + 我们维护的两张表） | 自己新增 47 个 `values-*`，清理一次删 139 条 × 39 文件 |
| 3 | `.github/workflows` ≤14 个 | 17 个手写工作流、3,209 行 YAML |
| 4 | 脚本不许吞错误（`\|\| true`、尾部 `echo done`），除非同一行用 `# allowed: <理由>` 明确豁免 | TEE 面板"九项检查全红但提示修好了"就是这个模式造成的 |
| 5 | 工作流/守卫脚本自身也要过闸门 | 守卫形同虚设 = 没有守卫 |
| 6 | 文档即真源：排除项、预算理由、allowance 理由必须写在仓库里 | 旧仓的决策只活在会话记忆里 |

## 人肉规矩（写在这里，评审时对照）

1. **只搬 delta，不复制上游文件**。共享组件/状态类型一律保留上游版本，只加我们缺的字段与文件。
   实测代价：把 55 个组件整体覆盖，一次冒出 12 个编译错、波及 6 个上游页面；把 `modulerepo` 状态换成我们的旧模型，一次 154 个错。
2. **同一功能只允许一代 UI**。旧仓 8 对 `Foo.kt` / `FooMiuix.kt` 并存，同一个 bug 要修两遍。
3. **单一真源**：uapi 只有一份；`target.txt` 只能由 `target-gen.sh` 写；keybox 判定只有 `keybox-health.sh`；T2 属性表只有 `bootstate.sh`。
4. **失败必须可见**：写操作要收集 stderr 并读回校验；禁止用尾部 `echo` 制造成功。
5. **一次提交一件事**：每个批次一个提交，提交信息写清"搬了什么、剔除了什么、为什么"。
6. **不做静默降级**：探测不到就显示"未知/未探测"，不要显示"不支持"或伪造成功。
